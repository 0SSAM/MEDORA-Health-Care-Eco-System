# منظومة النزاهة ومكافحة التلاعب والاحتيال والسرقة

## نطاق الإصدار

يضيف هذا الإصدار طبقة وقائية وقابلة للتدقيق لمؤشرات مخاطر النقد والمبيعات، المخزون، المشتريات، الوصفات، الصلاحيات، الهوية، والبيانات. النظام ينتج **إشارات مراجعة** ولا يعلن إدانة أي شخص، ولا ينفذ إجراءً تأديبيًا أو قانونيًا أو شراءً أو حظرًا تلقائيًا.

## الضوابط المنفذة

| المجال | الضابط | حالة الإنفاذ |
|---|---|---|
| العزل | كل قراءة وكتابة للقضايا تتحقق من المؤسسة والفرع على الخادم | مطبق |
| الصلاحيات | مراجعة القضايا محصورة بأدوار إدارية/مراجعة، مع تحقق عضوية المؤسسة وتعيين الفرع | مطبق |
| فصل المهام | سياسة خالصة تمنع اعتماد المستخدم لطلب أو تعديل أو إرجاع أنشأه بنفسه | مطبق في policy ومختبر |
| الإشارات | خصومات كبيرة، إلغاءات متكررة، تعديلات مخزون كبيرة، اعتماد ذاتي، تغيير صلاحية ذاتي، وتصدير خارج ساعات العمل | مطبق كتحليل قابل للتفسير |
| التحقيق | حالات جديدة، قيد المراجعة، احتواء، إغلاق، واستبعاد مع انتقالات محددة | مطبق |
| الأدلة | حفظ evidence JSON مرجعي مع رمز وملخص وملاحظة نتيجة عند الإغلاق/الاستبعاد | مطبق |
| التدقيق | تسجيل إنشاء القضية وانتقالاتها في سجل التدقيق ذي السلسلة الهاشية | مطبق |
| الواجهة | طابور مراجعة، ملف أدلة، تصفية، فتح قضية، احتواء، إغلاق موثق، واستبعاد موثق | مطبق |
| الخصوصية | لا كاميرا، لا ميكروفون، لا بصمة سلوكية خفية، ولا اتهامات تلقائية | مقفول افتراضيًا |

## قواعد التحقيق

لا يمكن إغلاق أو استبعاد قضية دون `resolutionCode` و`resolutionNote`. الانتقالات غير الصالحة مرفوضة خادميًا. الاحتواء حالة مؤقتة لا تثبت الذنب. يجب أن يراجع المسؤول الدليل من مصدر العمل الأصلي قبل أي إجراء تشغيلي أو موارد بشرية أو قانوني.

## التحقق

- اختبار سياسة مكافحة الاحتيال: 5 اختبارات ناجحة.
- المجموعة الكاملة: 352 اختبارًا ناجحًا و5 اختبارات متخطاة بسبب اعتمادها على قاعدة بيانات تكاملية غير متاحة في البيئة الحالية.
- TypeScript: ناجح.
- البناء الإنتاجي: ناجح.
- التحقق البصري: الصفحة الرئيسية تعمل بدون أخطاء واجهة ظاهرة، ومساحة مكافحة الاحتيال محملة كحزمة ديناميكية مستقلة.

## حدود الإصدار ومتطلبات التشغيل

هذه الطبقة لا تستنتج وجود سرقة من تلقاء نفسها ولا تستبدل المصالحات المحاسبية أو جرد المخزون أو سياسات الموارد البشرية أو الإبلاغ القانوني. ما زال ربط إشارات `assess` بأحداث البيع والمخزون والمشتريات الحية يحتاج تعريفًا تشغيليًا لكل حدث وموافقة مالك العملية حتى لا تنتج تنبيهات مضللة. كما يجب توفير بيئة staging منفصلة لاختبارات قاعدة البيانات التكاملية قبل تفعيل أي إجراء تشغيلي حساس.

يُحظر استخدام النتائج كأداة مراقبة شخصية أو تمييز أو عقوبة آلية. يجب تحديد مدة الاحتفاظ، أصحاب الوصول، آلية الاعتراض، ومراجعة قانونية/موارد بشرية قبل استخدام أي قضية في قرار يمس موظفًا أو متعاقدًا.
