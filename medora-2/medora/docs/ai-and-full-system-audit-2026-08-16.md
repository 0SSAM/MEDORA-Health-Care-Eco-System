# تقرير دمج الذكاء الاصطناعي والتدقيق الشامل — 16 أغسطس 2026

## النطاق

أضيفت ثلاث قدرات استشارية محكومة داخل MEDORA: تحليل المشتريات، دعم اتخاذ القرار التشغيلي، واقتراحات التطوير المبنية على بيانات النظام. تعمل جميعها داخل نطاق المؤسسة والفرع، وتستخدم بيانات تشغيلية مجمعة، وتُسجل النتائج للمراجعة البشرية. لا ينشئ النظام أمر شراء تلقائيًا، ولا يصدر قرارًا سريريًا أو ماليًا أو وظيفيًا أو تنظيميًا آليًا.

## ما تم تنفيذه

| المجال | التنفيذ | ضابط الأمان |
|---|---|---|
| تحليل المشتريات | تحليل الطلب التاريخي، المخزون، طلبات الشراء، مقارنة الموردين، وأعلام الشذوذ | النتيجة توصية فقط ولا توجد mutation لتحويلها إلى أمر شراء |
| دعم اتخاذ القرار | موجز مؤشرات التشغيل والاستثناءات مع دليل وقيود | مراجعة المستخدم المخوّل إلزامية والنتيجة استشارية |
| اقتراحات التطوير | اقتراحات تحسين مرتبطة بمؤشرات المبيعات والمخزون والطلبات والحالة التشغيلية | قبول بشري موثق ولا يوجد تنفيذ أو تغيير تلقائي |
| الحوكمة | تحقق من JSON المنظم، نطاق ثقة 0..1، حقول الدليل والقيود، وتسجيل الحالة | فشل التحقق يمنع حفظ النتيجة |
| العزل | المؤسسة والفرع والاختصاص تمر عبر عقد tRPC وتتحقق من صلاحية الإدارة | لا تُعرض نتيجة خارج النطاق المطلوب |
| المراجعة | حالات generated وunder_review وaccepted وrejected وdismissed | القبول توثيقي ولا يمنح تفويضًا خارجيًا |
| الواجهة | وحدة عربية/إنجليزية ضمن مساحة العمل، مع حالات تحميل وخطأ وفراغ وتفاصيل الدليل | تحذير واضح بأن كل النتائج استشارية |

## التدقيق والإصلاحات

تمت مراجعة تركيب الراوتر الرئيسي، مخطط Drizzle، حدود النطاق المؤسسي، الواجهة الرئيسية، سجلات runtime، واختبارات الصلاحيات والعزل القائمة. عولجت مشكلة تكرار كتلة المهام في `todo.md`، وأعيد تقليل diff الملفات القديمة بعد اكتشاف أن تنسيقًا شاملًا كان سيحوّل ملفات كبيرة دون حاجة. أضيف اختبار عقد مستقل لمخرجات AI يرفض الكائنات الناقصة والثقة خارج النطاق والمخرجات غير الكائنية.

كما تم فحص سجلات الخادم والمتصفح وطلبات الشبكة بعد تشغيل مساحة العمل. لم تظهر أخطاء `500` أو `TypeError` أو فشل tRPC في الجولة المرئية. ظهرت فقط تحذيرات حجم chunks المعتادة من Vite، وهي تحسين أداء مستقبلي وليست عطلًا وظيفيًا.

## نتائج التحقق

| الفحص | النتيجة |
|---|---:|
| TypeScript (`pnpm exec tsc --noEmit`) | ناجح |
| اختبار عقد AI المركز | 3 ناجحة |
| الاختبارات الكاملة | 344 ناجحة، 5 متخطاة، 105 ملفات ناجحة وملف واحد متخطٍ |
| البناء الإنتاجي (`pnpm build`) | ناجح |
| الفحص البصري لمساحة العمل والصفحة العامة | ناجح؛ مساحة العمل تعمل مع جلسة مصادق عليها |
| فحص سجلات runtime بعد التشغيل | لا أخطاء runtime مرتبطة بالتغيير |
| فحص الأسرار الثابتة في الملفات الجديدة | لم تظهر مفاتيح API من الأنماط المفحوصة |
| ترحيل قاعدة البيانات | جدول `ai_insights` وترحيله غير هدّامين، والترحيل مطبق مسبقًا |

> الاختبارات المتخطاة هي اختبارات تكامل تعتمد على بيانات/اتصال قاعدة بيانات خارجي في بيئة الاختبار، وليست فشلًا في التطبيق. يجب تشغيلها في بيئة staging متصلة قبل الإنتاج.

## القيود المتبقية

يبقى استدعاء الجهات الحكومية والتأمين الخارجي مقفولًا حتى الحصول على التفويض الرسمي. ولا تُفعّل مراقبة أماكن العمل أو الكاميرات أو الميكروفونات أو القياسات الحيوية أو تقييم الموظفين تلقائيًا. كما أن نتائج AI تعتمد على توفر بيانات تشغيلية كافية؛ وعند نقصها يجب أن تعرض القيود بدل اختلاق تقديرات.

يحذر Vite من وجود chunks أكبر من 500 kB بعد التصغير، خصوصًا الحزمة الأساسية ومساحة Home. هذا لا يمنع البناء أو التشغيل، لكنه بند تحسين أداء لاحق يمكن معالجته بالتقسيم الديناميكي دون تغيير نطاق الأمان.

## قرار الجاهزية

حالة التغيير: **جاهز للمراجعة البشرية في بيئة staging**. لا يُنصح بتحويل نتائج الذكاء الاصطناعي إلى عمليات شراء أو قرارات حساسة دون اعتماد سياسة تشغيلية، تدريب المستخدمين، وربط سجلات المراجعة بمسؤول واضح.
