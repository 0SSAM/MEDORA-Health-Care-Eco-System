# تقرير مقارنة القدرات وخطة استكمال MEDORA

**تاريخ التحقق:** 17 أغسطس 2026
**النطاق:** MEDORA Health Care Eco System مقارنةً بقدرات منشورة رسمياً لدى Oracle وOdoo ودفترة وSAP. أما اسم **ارتقي** فلا يكفي وحده لتحديد منتج ERP واحد موثوق؛ لذلك لا تُنسب له خصائص محددة قبل تزويد MEDORA برابط المنتج الرسمي أو اسمه القانوني الدقيق.

> هذا تقرير فجوات وتنفيذ تقني، وليس ادعاءً بأن MEDORA معتمدة من أي مزود منافس أو متكاملة معه أو مكافئة له. لا تعني الجداول الداخلية أو شاشات الواجهة أن التكامل التنظيمي أو الطبي أو المالي الخارجي فعال.

## المنهج وحدود الدقة

اعتمدت المقارنة على صفحات المنتج الرسمية الحالية لـ Oracle وOdoo ودفترة وSAP، وعلى نموذج بيانات MEDORA وراوترات الخدمة ومسارات الواجهة واختبارات النظام الفعلية. وُسمت قدرة MEDORA بأنها **منفذة** فقط إذا كان لها نموذج/بيانات أو مسار خدمة محمي وواجهة تشغيلية، وليس لمجرد ورودها في خطة أو نص تسويقي.

| المنتج المرجعي | دلالة النطاق المقارن | مصدر رسمي |
|---|---|---|
| Oracle Fusion Cloud | ERP وSCM وHCM ومنصات صحية مؤسسية وتكاملات شركاء | [ERP][oracle-erp]، [SCM][oracle-scm]، [HCM][oracle-hcm]، [Health][oracle-health] |
| Odoo | تطبيقات معيارية مترابطة للمحاسبة والمخزون والمبيعات والتصنيع والموارد البشرية والويب | [التطبيقات][odoo-apps]، [المخزون][odoo-inventory]، [المحاسبة][odoo-accounting]، [التصنيع][odoo-manufacturing] |
| دفترة | إدارة أعمال إقليمية تشمل المحاسبة والمبيعات والمخزون والموارد البشرية والعملاء | [دفترة][daftra] |
| SAP | ERP وS/4HANA وسلسلة إمداد وتحليلات وحلول قطاع صحي | [ERP][sap-erp]، [S/4HANA][sap-s4]، [SCM][sap-scm]، [Healthcare][sap-health] |
| ارتقي | غير قابل للتحديد بدقة من الاسم وحده | يحتاج رابطاً رسمياً مؤكداً |

## ما لدى MEDORA فعلياً

MEDORA لا تبدأ من الصفر. فهي تملك أساساً متخصصاً للرعاية الصحية يتجاوز كثيراً من تطبيقات الأعمال العامة: عزل **المؤسسة والفرع والاختصاص القضائي**، تحقق عضوية وصلاحيات على الخادم، سجل تدقيق موقع، فصل صريح بين العرض والإنتاج، نقطة بيع ومرتجعات وشيفتات، مخزون دفعات وفق FEFO، موردين وطلبات وأوامر واستلامات، أساس دفتر أستاذ ومراكز تكلفة وفترات مالية ومصروفات أخرى وتحويلات بين الفروع، سجلات خصوصية صحية، توصيات ذكاء اصطناعي مقيدة بالمراجعة البشرية، فحص احتيال، قاعدة معرفة سياسات، نسخ احتياطي موثق، وموصلات تنظيمية وتأمينية **مغلقة آمنياً** حتى اعتمادها. كما توجد قواعد CRM وHR وCall Center وCustomer Care.

| المجال | الحالة الحالية في MEDORA | تقييم المقارنة |
|---|---|---|
| POS والصيدلية | منفذ: بيع، مرتجعات، شيفتات، قراءة ومسارات جهازية، FEFO ودفعات | مناسب كنواة صيدلية؛ لا يُدعى تكامل جهاز أو جهة رسمية غير معتمد |
| المشتريات والموردون | منفذ: دليل موردين، طلبات، أوامر، استلامات، تقارير وفلاتر | ينقصه بوابة موردين موثقة وشبكة توريد خارجية |
| المالية | منفذ: أساس GL، مراكز تكلفة، فترات، مصروفات أخرى، تحويلات بين فروع | ينقصه التخطيط والالتزام والميزانيات والتجميع المالي المنضبط |
| الموارد البشرية | منفذ: ملفات موظفين، شيفتات/حضور وطلبات أساس | لا يوجد حساب رواتب قانوني أو إيداع/إقرار نظامي |
| العملاء والخدمة | منفذ: CRM مقيد بالموافقة وCustomer Care وCall Center أساس | لا يوجد تسويق أو رسائل خارجية تلقائية بلا موافقة وقناة معتمدة |
| المخزون وسلسلة الإمداد | منفذ: دفعات وFEFO وتنبيهات واستلام أساس | ينقصه دفتر مواقع WMS، put-away/pick-pack، وجرد دوري متحكم به |
| الذكاء الاصطناعي والتحليلات | منفذ: اقتراحات إرشادية، كتابة ذكية اختيارية، إنذارات وتقارير محكومة | ليس بديلاً عن قرار طبي/مالي؛ ينقصه نموذج دلالي BI موسع |
| الامتثال الصحي | منفذ داخلياً مع موصلات fail-closed | eRx والضرائب والتأمين والجهات الحكومية تتطلب موافقات واختبارات رسمية |

| P2 | تصنيع وجودة وصيانة | موجود لدى Odoo/SAP ومناسب لجهات صناعية | ليس عاماً لكل منشأة صحية؛ يبنى فقط عند الحاجة القطاعية |

## ما تم تنفيذه تلقائياً في هذه الدورة

أُضيف **صندوق المراجعة الموحد** إلى مركز العمليات ليغطي أهم فجوة تشغيلية يمكن تنفيذها الآن من دون اختراع موافقات عامة أو تخفيض الحماية.

| خاصية التنفيذ | السلوك المتحقق |
|---|---|
| مصادر البيانات | طلبات الشراء، طلبات الإجازة، إقفالات النقد، المصروفات الأخرى، والتحويلات بين الفروع التي هي بالفعل في حالة مراجعة معلقة |
| أقل إفصاح ممكن | المصدر، معرّف السجل، الحالة، الوقت، والعدد فقط؛ لا عنوان ولا مبرر ولا مبلغ ولا بيانات مريض أو موظف |
| العزل | تحقق خادمي للمؤسسة والفرع والاختصاص والعضوية، مع صلاحية إدارة العمليات |
| عدم تجاوز الحوكمة | الصندوق لا يحتوي اعتماداً أو رفضاً؛ المستخدم يعود إلى دورة السجل الأصلية وسجل تدقيقها |
| قابلية التنبؤ | ترتيب زمني ثابت وحد أقصى للنتائج وعدادات لكل مصدر |
| التحقق | اختبارات نطاق/عقد/ترتيب، ثم TypeScript، ومجموعة Vitest الكاملة، وبناء الإنتاج، وفحص واجهة RTL |

## نتيجة التحقق لهذه الدورة

نجح التحقق البرمجي في **510 اختباراً**، مع **8 اختبارات متخطاة بيئياً**، ونجحت ترجمة TypeScript وبناء الإنتاج. ظهر صندوق المراجعة الموحد في مركز العمليات بحساب العرض ضمن النطاق المعزول مع رسالة واضحة بأنه قراءة فقط ولا توجد عناصر معلقة في بيانات العرض.

## قرار التنفيذ التلقائي التالي

لا ينبغي تحويل كل ما لدى المنافسين إلى كود دفعة واحدة؛ بعضه يحتاج سنداً قانونياً أو اعتمادات أو مزوداً خارجياً. الترتيب الآمن المقترح هو: **(1)** مصفوفة فصل مهام قابلة للتدقيق، **(2)** ميزانية والتزامات مالية بعد اعتماد سياسة محاسبية، **(3)** دفتر مواقع مخزنية وحركات محكومة، **(4)** أدلة مستندات وبوابة موردين بعد هوية المورد والاحتفاظ، ثم **(5)** تقارير محكومة وتوزيع خارجي بعد اعتماد القناة. ستظل الوظائف التنظيمية والصحية والرواتب والتوقيع المؤهل بوابات خارجية حتى يتوافر الإثبات المطلوب.
