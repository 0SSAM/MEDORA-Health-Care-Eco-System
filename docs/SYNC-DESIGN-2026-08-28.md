# تصميم المزامنة دون اتصال — Offline-First Sync Design (مقترح)

**2026-08-28 — وثيقة تصميم فقط (PSD): التنفيذ لاحقًا كـ milestone مستقل.**

## المشكلة الموثقة

`docs/MEDORA-BACKUP-SYNC-AUDIT-2026-08-28.md` حددت فجوة: «sync جزئي — offline-first مفقود».
هذا التصميم يسد الفجوة على الورق.

## الأهداف

1. استمرار العمل عند انقطاع الشبكة (نقاط بيع/صيدليات ميدانية).
2. تطبيق موثوق للتغييرات عند عودة الاتصال.
3. حسم تعارضات بسيط (last-write-wins + نسخ احتياطية).

## المكونات المقترحة

| المكوّن | الوصف |
|---|---|
| `Outbox` (جدول) | كل كتابة محلية تُسجَّل كحدث `{entity, key, payload, ts, deviceId}` |
| `SyncEngine` (وحدة) | دفع outbox بتسلسل، إعادة محاولة، استقبال delta منذ `cursor` |
| `ConflictResolver` | LWW افتراضي + اختيار الحقل حسب الأولوية (حقول سريرية تتطلب مراجعة) |
| `LocalStore` | IndexedDB (واجهة) / SQLite (سطح مكتب) لتخزين نسخة العمل |
| `version` لكل صف | `updatedAtMs` + `deviceId` لحسم الترتيب |
| الجدولة | مؤقت كل 30 ثانية أو عند استعادة الاتصال (`navigator.onLine`) |

## خطة التنفيذ المقترحة (مراحل)

1. **P1**: عمودا `updated_at`/`device_id` + Outbox عام لكل الجداول الحرجة (sales, catalog_items, inventory).
2. **P2**: SyncEngine في `server/domain/sync.ts` + endpoint tRPC `sync.push`/`sync.pull`.
3. **P3**: LocalStore IndexedDB في الواجهة + تبديل حالة اتصال.
4. **P4**: اختبارات تعارض (LWW) + لوحة حالة مزامنة في `/admin`.

## الخلاصة الصادقة

لا يوجد كود مزامنة في هذه الدفعة؛ الملف **تصميم معتمد** لإزالة الغموض وتوجيه التنفيذ القادم.
