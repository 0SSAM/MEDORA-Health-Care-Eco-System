# مصفوفة خواص دفترة مقابل MEDORA

تستند هذه المراجعة إلى صفحة دفترة الرسمية التي تعرض وحدات المبيعات والفواتير ونقاط البيع والعروض والأقساط والعملاء والولاء والمخزون والمشتريات والحسابات والموارد البشرية والتشغيل والتطبيقات المحمولة، وإلى صفحات نقاط البيع الرسمية المشار إليها من الموقع.[^1][^2] لا تعني قائمة دفترة أن كل خاصية متاحة في كل خطة أو بلد؛ التصنيف هنا مبني على كود MEDORA الحالي.

| المجال | الخاصية المطلوبة/المعلنة | حالة MEDORA | دليل التنفيذ أو القيد |
|---|---|---|---|
| المبيعات | POS، فتح فاتورة، سلة، طرق دفع، خصم محكوم | **مدمج** | `PointOfSaleWorkspace` و`erp.pos.commitSale` مع عزل المؤسسة/الفرع/الاختصاص والتحقق الخادمي. |
| المبيعات | البحث بالباركود | **مدمج الآن** | `availableStock` يبحث في `products.barcode`، والواجهة تدعم قارئ USB/إدخال لوحة المفاتيح عبر Enter. |
| المبيعات | تعليق واسترجاع الفاتورة | **مدمج الآن** | جدول `held_invoices` وإجراءات `holdInvoice/listHeldInvoices/restoreHeldInvoice`، مع سجل تدقيق. النطاق مقيد بالكاشير والفرع والاختصاص. |
| المبيعات | طباعة الإيصال ومشاركته | **مدمج الآن** | طباعة محلية بعد نجاح البيع ومشاركة نص غير حساس عبر رابط WhatsApp؛ لا تُرسل بيانات صحية أو أسرار. |
| المبيعات | عروض/ترويج وخصومات | **جزئي/مدمج محكوم** | `promotions` و`commitSale` يتحققان من النطاق والصلاحية والحدود. يحتاج العرض الإداري المرئي إلى تدقيق وظيفي منفصل إذا أريدت دورة كاملة. |
| المبيعات | مرتجعات وإشعارات دائنة | **مدمج خادميًا/واجهة جزئية** | جداول `salesReturns` و`taxInvoices` موجودة وإجراءات ERP محكومة؛ يلزم استكمال تجربة الكاشير إذا كان المطلوب تشغيلها من POS مباشرة. |
| الفواتير | قوالب ضريبية وفاتورة محلية | **مدمج** | `TaxInvoiceWorkspace` وإجراءات قوالب وفواتير محلية. الإرسال الحكومي الخارجي يظل fail-closed حتى الاعتماد والاعتمادات. |
| الفواتير | الفاتورة الإلكترونية حسب الدولة | **مجهز ومحجوب** | حزم الامتثال والأدلة والتحقق موجودة، لكن بوابات الجهات الرسمية لا تُفعّل دون أذونات واعتمادات حكومية. |
| المخزون | المنتجات، الدفعات، FEFO، الكميات، إعادة الطلب والانتهاء | **مدمج** | جداول المنتجات والدفعات، البحث الموثق، اختيار الدفعات حسب الانتهاء، والتنبيهات المجدولة. |
| المخزون | الجرد والحركات المخزنية | **مدمج جزئيًا** | وحدات سلسلة الإمداد وoffline drafts ومخزون الدفعات موجودة؛ يجب اختبار دورة الجرد الواقعية على بيانات تشغيلية قبل اعتبارها مكتملة تشغيليًا. |
| المشتريات | موردون، طلبات شراء، مراجعة AI بشرية، مكافحة التلاعب | **مدمج محكوم** | `procurementRequests`، بوابة المراجعة البشرية، حوكمة AI، وسجلات anti-fraud موجودة. |
| الحسابات | دليل حسابات، مصروفات، أصول، مراكز تكلفة، شيكات | **جزئي/خاص بالصحة التشغيلية** | توجد تقارير وتشغيل مالي وفواتير وطلبات وتأمين، لكن لا يظهر من الجرد الحالي دفتر حسابات عام كامل مماثل لوحدة محاسبة دفترة؛ يلزم مشروع محاسبة مستقل إذا كان مطلوبًا. |
| العملاء | ملفات العملاء، CRM، متابعة العملاء، مركز الاتصال | **مدمج** | `customerProfiles` و`crm` و`customerCare` و`callCentre`. |
| الولاء | نقاط ولاء، اشتراكات، عضويات، أرصدة | **غير ظاهر كدورة كاملة** | لا توجد في الجرد الحالي جداول/إجراءات واضحة لدورة الولاء والعضويات؛ تحتاج تصميمًا مستقلًا مع ضوابط مالية. |
| الموارد البشرية | موظفون، أدوار، حضور، إجازات | **مدمج** | `employeeProfiles` و`employeeAttendance` و`employeeLeaveRequests` وإدارة الحسابات والصلاحيات. |
| التشغيل | أوامر شغل، حجوزات، إيجارات، تتبع وقت، تصنيع | **جزئي حسب المجال** | توجد وحدات عمليات وصحة ومواعيد وتذاكر؛ أوامر الشغل/الإيجارات/التصنيع العام ليست مكافئة مكتملة في الجرد الحالي. |
| الرعاية الطبية | مواعيد، مرضى، وصفات، تأمين، مطالبات | **مدمج ومتخصص** | جداول المرضى والزيارات والمواعيد والوصفات والتأمين والمطالبات، مع مراجعة صيدلانية وحواجز نطاقية. |
| التقارير | تقارير، تشغيلات، تسليمات، لوحات AI | **مدمج** | `reportDefinitions` و`reportRuns` و`reportDeliveryAttempts` و`AiInsightsWorkspace`. |
| التطبيقات المحمولة | واجهة RTL متجاوبة، جرد، حضور، POS | **مدمج واجهيًا** | تم اختبار نقاط الاستجابة وRTL آليًا؛ اختبار جهاز فعلي يظل قبولًا تشغيليًا للمستخدم. |
| التكاملات الحكومية | ETA/الفاتورة الرسمية والجهات الحكومية | **مجهز ومحجوب** | التصميم fail-closed؛ لا يجوز تجاوز بوابة الاعتماد أو اختلاق بيانات الاعتماد. |

## الخلاصة

الخواص الأساسية التي طلبها المستخدم من منظور ERP صيدلي/رعاية صحية—POS، المخزون والدفعات، المشتريات مع AI محكوم، الحسابات التشغيلية، العملاء، الموظفون، مكافحة الاحتيال، التقارير، الوصفات، التأمين، والامتثال—موجودة بدرجات متفاوتة في MEDORA. الإضافات المنفذة في هذه الدورة هي **الباركود، الفواتير المعلقة الخادمية مع التدقيق، والطباعة/المشاركة بعد البيع**.

أما **دفتر الحسابات العام، الولاء والعضويات، التصنيع، الإيجارات، وبعض دورات التشغيل العامة** فلا ينبغي الادعاء بأنها مكتملة لمجرد وجود تقارير أو جداول قريبة. هذه البنود مصنفة جزئية أو غير ظاهرة وتحتاج نطاقًا مستقلًا حتى لا تُبنى محاسبة أو نقاط ولاء غير آمنة فوق نموذج غير مكتمل.
