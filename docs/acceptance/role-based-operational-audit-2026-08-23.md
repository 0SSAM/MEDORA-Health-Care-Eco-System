# MEDORA — تدقيق القبول التشغيلي متعدد الأدوار

**التاريخ:** 23 أغسطس 2026
**النطاق:** MEDORA Health Care Eco System، حساب العرض المعزول، عقود الخادم والواجهة، ومراجعة واجهة غير هدّامة.
**القرار:** لا يوجد عيب وظيفي جديد قابل لإعادة الإنتاج في الدفعات المنفذة؛ لذلك لم يُجرَ تعديل وظيفي أو توسعة صلاحيات في هذه الجولة.

> **قاعدة الدليل.** لا تعد الشاشة المرئية أو عنصر الواجهة إثباتاً للصلاحية بمفرده. لا تسجل العملية باعتبارها ناجحة إلا إذا حمتها عقود الخادم والنطاق المؤسسي والفرعي والاختصاصي، أو أثبتها تدفق عرض معزول قابل لإعادة الإنتاج.

## 1. حدود البيئة ومنهج القبول

بيئة العرض تحتوي حسابات تركيبية ومؤسسة عرض وفرع عرض فقط. يحتفظ حساب `Test` بدور التطبيق `manager`، ويعامل كـ`org_admin` داخل مؤسسة العرض وحدها؛ لا يصبح مديراً عاماً ولا يرى مؤسسة إنتاج. جميع الكتابات المحمية أو الإدارية في جلسة العرض ترفض قبل معالج الإجراء وتسجل كمحاكاة غير محفوظة. لذلك اختبرت هذه الجولة القراءة، المسارات، الرفض الآمن، والعقود؛ ولم تجر أي عملية سريرية أو مالية أو إدارية دائمة.

| طبقة التحقق | الدليل المنفذ | النتيجة |
|---|---|---|
| عزل العرض وصلاحيات الإدارة | 11 ملف عقد وصلاحيات، 39 حالة | **39 ناجحة**، وحالة واحدة متجاوزة عمداً لأنها تتطلب بيئة إضافية |
| POS والمخزون والوصفات والمشتريات والتقارير وخدمة العملاء | 32 ملف تدفق وسياسة، 94 حالة | **94 ناجحة**، وملف واحد متجاوز عمداً لأنه يتطلب قاعدة اختبار معزولة |
| مراجعة Test الحية | تسجيل الدخول، مساحة العمل، الإفصاح، الفرع، لوحة الإدارة | **ناجحة** من دون كتابة دائمة |
| مراجعة تخطيط الهاتف | صفحات مساحة العمل والإدارة عند 390×844 | **ناجحة بصرياً**؛ وليست اختبار تفويض لهوية دور مستقلة |

## 2. نتيجة المسارات بحسب الدور

| الدور المطلوب | المقابل المطبق في MEDORA | المسارات أو الضوابط التي تم التحقق منها | الحالة |
|---|---|---|---|
| Test / العرض | `manager` + عضوية عرض `org_admin` فقط | الدخول، شريط القراءة فقط، مؤسسة وفرع العرض، لوحة الإدارة المعزولة، رفض الكتابة المحمية | **متحقق** |
| الصيدلي | `pharmacist` + `clinical_lead` | نطاق الوصفات، بوابات الوصول السريري، الاستهلاك المقيد، المراجع الدوائية، وقراءة الأصناف ضمن النطاق | **متحقق بالعقد**؛ لا وصفة أو مريض حقيقيان |
| الكاشير | `cashier` + `staff` | POS، مخزون البيع المتاح، ترتيب المخزون، الوردية النقدية، المرتجع، أرقام الفاتورة، وحدود المالية والمشتريات | **متحقق بالعقد** |
| المبيعات | صلاحيات POS وجهات الاتصال بحسب الدور | بيانات العميل والمبيعات، المعاينة الضريبية، المرتجعات، وسياسة الفاتورة | **متحقق بالعقد** |
| المشتريات | `operations_manager` أو دور إداري مؤسسي | الموردون، سياسة أوامر الشراء، التقارير والأرصدة، وشرط الدور الإداري قبل القراءة المالية | **متحقق بالعقد** |
| المستودع | مسارات مخزون وصلاحيات عمليات مقيدة | FEFO، جرد المخزون، سياسة تعديل المخزون، تنظيم الإشارات، وعزل الفرع | **متحقق بالعقد** |
| خدمة العملاء ومركز الاتصال | وحدات CRM/خدمة العملاء المقيدة | سياسة خدمة العملاء، الوحدات الثانوية، وتقييد الوصول الإداري للمسارات الحساسة | **متحقق بالعقد**؛ الاتصال الخارجي غير مشغل |
| الطبيب | لا هوية عرض مستقلة؛ سياسة سريرية مقيدة | بوابات السريري والوصفات واختصاص البلد ورفض الاستخدام خارج النطاق | **متحقق بالعقد فقط**؛ لا ينسب إلى حساب صيدلي |
| المدير | `manager` و`operations_manager` عند العضوية المؤسسية | مؤشرات التشغيل، SLA، مبرر القرار، وحدود القراءة التشغيلية | **متحقق بالعقد وبواجهة العرض** |
| صاحب القرار | وصول تقارير مقيد بالعضوية الإدارية | التقارير، التصدير الآمن، الجدولة، والعزل المالي | **متحقق بالعقد** |
| Admin | مدير عام منفصل أو عضو `org_admin` ضمن مؤسسة محددة | إدارة الموظفين، العضويات، الفروع، المصفوفة المقروءة فقط، والتصدير المفلتر | **متحقق في لوحة العرض المعزولة** |

## 3. الأدلة التشغيلية المختصرة

### 3.1 Test / العرض ولوحة الإدارة

أثبتت جلسة `MEDORA Showcase Manager` في المتصفح أن مساحة العمل تعرض الدور `manager`، وفرع العرض التجريبي المعزول، وشريط **«وضع القراءة فقط · جلسة عرض معزولة»**. وصف الشريط بوضوح أن العمليات محاكاة ولا تحفظ، وأن زر تسجيل الدخول يبدأ المسار المعتمد فقط ولا يمنح صلاحية داخل جلسة العرض. ظهرت لوحة الإدارة لمؤسسة **MEDORA Investor Showcase** وحدها، وعرضت ثلاثة حسابات تركيبية فقط: الكاشير والصيدلي ومدير العرض. لم تظهر مؤسسة إنتاج أو عضوية خارج نطاق العرض.

| عنصر محقق | النتيجة | الحاجز الذي حمى النتيجة |
|---|---|---|
| عزل المؤسسة والفرع | مؤسسة عرض واحدة وفرع عرض واحد | سياسة العرض وجلسة النطاق الخادمية |
| سطح الإدارة | قائمة موظفين مفلترة، فلاتر، ترقيم، ومصفوفة ثابتة | صلاحية العضوية المؤسسية والتحقق الخادمي |
| حماية الحساب المحمي | مدير العرض مميز كدور محمي | حدود تعديل الأدوار المحمية |
| عدم الحفظ في العرض | يعامل كرفض متوقع في عقود الحماية | حاجز الكتابة المركزي قبل معالج الإجراء |

### 3.2 الدفعة الآلية للعقود

نفذت الدفعة الأولى ملفات العرض والإدارة والمالية والوحدات الثانوية وذكاء العمليات. نجحت **39 حالة في 11 ملفاً**، مع تجاوز حالة واحدة عمداً مرتبطة ببيئة إضافية. نفذت الدفعة الثانية ملفات POS والمخزون والوصفات والمشتريات والتقارير وخدمة العملاء. نجحت **94 حالة في 32 ملفاً**، وتجاوز ملف واحد اختبار معاملة عرض حية لغياب إعداد قاعدة اختبار معزولة ومفاتيح الأمان اللازمة له.

تحقق اختبار تسليم بريد التقارير من الفشل المحدود عند غياب عنوان خدمة الدخول: سجل الإعداد الناقص ثم أعاد نتيجة آمنة ولم يرم الخطأ إلى المجدول. هذه **ليست** دليلاً على إرسال بريد إنتاجي، بل دليل أن المسار يفشل بأمان عند عدم التهيئة.

| حزمة الأدلة | ما تحميه | الحالة |
|---|---|---|
| `showcase-bootstrap`, `showcase.guard`, `showcase-admin-policy` | هوية العرض، حظر الكتابة، وعدم التصعيد إلى مدير عام | ناجحة |
| `financial-role-guard`, `procurement-report-role` | منع الكاشير من القراءة المالية والمشتريات | ناجحة |
| `secondary-modules-role-acceptance`, `operations-hr-role` | بوابات HR وCRM وخدمة العملاء ومركز العمليات | ناجحة |
| `pos-*`, `cash-shift-policy`, `consumer-returns-policy` | نطاق POS والوردية والمرتجع ومخزون البيع | ناجحة |
| `clinical-access-policy`, `prescription-*`, `catalog-prescription` | الوصول السريري المقيد، الوصفات، واختصاص البلد | ناجحة |
| `procurement-policy`, `supplier-directory`, `report-*` | الموردون والمشتريات والتقارير والتصدير والجدولة | ناجحة |

## 4. الواجهة وسهولة الاستخدام

في عرض سطح المكتب لحساب Test، كانت وحدات المساحة والبحث الذكي واختيار الفرع ومسار لوحة الإدارة مرئية وقابلة للوصول، مع إفصاح متكرر ومباشر عن كون البيانات تجريبية وعن منع الاتصال الخارجي. في المراجعة الهاتفية عند 390×844 تحولت لوحة الإدارة إلى بطاقات موظفين ومصفوفة امتيازات عمودية؛ لم يظهر تمرير أفقي غير مقصود في اللقطات. بقيت مراجعة الهاتف **فحصاً بصرياً فقط**، لأن لقطة المعاينة لا تحل محل جلسة هوية دور مستقلة.

لم ينفذ إرسال أو حفظ أو حذف أو تعديل موظف أثناء المراجعة الحية. ذلك مقصود: لا ينبغي أن يحول اختبار القبول إلى تعديل صلاحيات أو سجلات حتى في بيئة العرض ما دام الاختبار يمكن إثباته بعقود الحماية.

## 5. القيود والعناصر التي تتطلب اعتماداً حياً

| المجال | الحالة | ما يلزم للاعتماد الحقيقي |

| هوية طبيب أو مشتريات أو مبيعات أو خدمة عملاء مستقلة | مقيد بالبيئة | حسابات عرض مصرح بها ومقيدة بالمؤسسة والفرع لكل دور |
| المرضى والوصفات والصرف السريري | محجوب بأمان | بيانات اختبار سريرية معتمدة، موافقة مسؤول سريري، وتشفير وسياسات تشغيل |
| WhatsApp ومركز الاتصال | غير معتمد حياً | sandbox رسمية، مفاتيح موفر مصرح بها، acknowledgements وretry قابل للتدقيق |
| البريد المجدول | فشل آمن متحقق فقط | موفر بريد اختبار أو إنتاج معتمد وأسرار صحيحة وقواعد موافقة |
| الدفع والتأمين والجهات الحكومية | غير معتمد حياً | عقود تكامل رسمية وبيئة مزود اختبار واختبار قبول مفوض |
| الكاميرا وData Matrix والبلوتوث والطابعة | غير مختبر جهازياً | أجهزة فعلية ومتصفح أو نظام مستهدفان وأذونات مستخدم |
| اختبار معاملة العرض الحية المعزولة | متجاوز عمداً | `TEST_DATABASE_URL` معزول وإشارات أمان الاختبار المطلوبة |

## 6. النتيجة وخطة المعالجة

لم يظهر من هذه الجولة إخفاق قابل لإعادة الإنتاج يستدعي إصلاحاً. لم تضف صلاحيات، ولم توسع استعلامات، ولم يخفف عزل المؤسسة أو الفرع أو الاختصاص، ولم تنشأ بيانات مرضى أو عمليات دائمة. تفتح معالجة منفصلة فقط عند توفر دليل جديد قابل لإعادة الإنتاج، ويجب أن تتضمن أقل تعديل آمن واختبار انحدار مستهدف قبل إعادة فحص المجموعة كاملة.
